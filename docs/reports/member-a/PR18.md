## 3. The six verbs

Role gate in the handler; both scope guards left in the service, where a transaction is open and
the stored row is available. Never composed, chosen by verb, exactly as §3's table has it.

`EXAM_LIST` needed **no store change**. `AuthoredVersionRow` deliberately carries no question
count and its javadoc argues the case: the count is one aggregate over a different table,
`ExamRepository.countQuestionsByVersion` already answers it in one grouped read for a whole
screenful, and a correlated count on the versions query would be a second expression of one fact.
So `list()` zips three existing reads. **This retires ask 4 of PR17** — I asked you for a store
change that the store had already argued against.

### 3.1 The submit hook, and the sentence that was not enough

Your §5.5 ruling says the handler calls `versionSubmitted` after commit. Writing it surfaced that
the ruling's own wording — "once its transaction has committed **and** `submitForApproval` returned
`OK`" — is satisfiable by a call placed *inside* `Transactions.inTx`, where the service has
returned `OK` and nothing has committed. That reproduces the exact bug the amendment kills.

The contract now says **outside `Transactions.inTx`, on the returned outcome**, and the test holds
it there by observing the mechanism rather than a proxy: it records what
`RecordingTransaction.committed()` said *at the moment the hook ran*. `MockSessions` flips that
flag inside the stubbed `tx.commit()`, and `Transactions.java:114` commits after the lambda returns
and before `inTx` does, so the mock's flag flips at exactly the production commit point.

**Planted, not assumed.** Moving the call inside the lambda fails that one test and leaves all 21
others green. That is the whole reason it is written the way it is.

## 4. ⚑ Why §7 does not freeze

Full argument in the message of 2026-08-24 and in the contract header. In short, a cold read before
any generator code was written found that §7 does not determine an answer for quotas whose
candidate pools **cross** rather than nest:

> Bank: Recursion 6 (4 Hard), Algebra 2 Hard + 20 Easy. Quotas `("Recursion", any=5)` and
> `(null, hard=5)`. Every bucket passes — Recursion 5≤6, Hard 5≤6, course 10≤28 — but the pools
> overlap in 4 questions, so the union is 8 and 10 are needed.

No bucket is short, so §7.3 names no row, and `AutoComposeResult`'s compact constructor throws on
the empty report: `INTERNAL` and a stack trace on the F3.3 verb. Separately, §7.4's
most-constrained-first is a greedy order rather than a matching, and greedy loses on crossing pools
— emitting `(null, HARD, 3, 4)`, whose `missing()` is 0, so the client renders a shortfall claiming
nothing is missing.

**Building `AutoComposer` against an undecided rule is the expensive thing to unwind**, so it is
split out. `EXAM_AUTO_COMPOSE` is registered nowhere and
`ExamHandlersTest.Registration.exactlyTheSixVerbs` asserts the verb set, so restoring it takes a
deliberate test change rather than a quiet addition.

## 5. What the cold audit found, after the code was written

Run against the code, not the plan. Nine findings across two runs; the four that changed code:

### 5.1 My wiring guard could not catch the thing its own comment claimed

`new (\w*Exam\w*Handlers?)\(` cannot match `new AutoComposeHandlers(` — no "Exam" in the name — and
the comment beside it said "this is what will catch `AutoComposeHandlers`". It also matched nothing
at all today, so the loop body never ran and the test asserted precisely nothing while reading as
coverage.

**This is the second time I have written that defect**; a cold audit found the same too-narrow
regex in `BankWiringGuardTest`. So the fix is not a wider regex. It now asks the **filesystem**:
every `*Handlers.java` in this feature's own package must be on the guarded list. A handler in this
feature is a file in this feature, whatever anyone names it, and the list is asserted non-empty so
it cannot go vacuous again.

### 5.2 `quotaProblem` was looser than the collation of the pool it protects

`seenTopics.add(quota.topic())` on a `HashSet<String>` is case- and accent-sensitive. The pool is
selected with `qv.topic = :topic` against a `utf8mb4_unicode_ci` column. So `"Algebra"` and
`"algebra"` passed as two distinct buckets and drew from one set of rows — **the exact hazard the
rule exists to prevent**, not an edge case beside it. C-7 / ADR-016: at least as strict as the
collation, in every dimension. P-6 class.

Fixed by reusing rather than reimplementing: `QuestionValidator.sameTopic` delegates to
`sameAnswer`, whose four folding steps are already measured against the real database and whose
javadoc states the one-directional goal. A second expression of "what the database calls the same
string" is the defect P-6 is about. 6 new tests pin it, including a negative case so the fold is
not blunt.

It was **latent** — `quotaProblem` has no production caller while `EXAM_AUTO_COMPOSE` is
unregistered — which made this the cheapest possible moment.

### 5.3 A javadoc that described a refusal that cannot happen

`ExamHandlers`'s class javadoc counted `EXAM_LIST` among "the other five" that check authorship and
answer `NOT_FOUND`. It does neither: its scope is an author predicate in the SQL of both reads, and
it has no `NOT_FOUND` path. Your §3 table gets this right. Corrected, because that sentence is what
a reviewer uses to decide which guard a verb should wear.

### 5.4 Tests that read stronger than they were

Every handler-to-service call was stubbed and verified with `any()`, so a handler forwarding a
*different* payload instance or another caller's context would have left all of them green. New
`Forwarding` group pins payload and caller identity with `same()` across all six verbs. And
`theWrongPayloadTypeIsASentence` asserted "opens no transaction" via the commit flag, which is also
what a rollback leaves behind; it now asserts `verifyNoInteractions(session)`.

## 11. The assembly commit

```java
ApprovalService approvals = registerApprovalFeature(router, notifications, sessionFactory);
new ExamHandlers(sessionFactory,
        new ExamService(new ExamBuildRepository(), new ExamRepository(),
                new CourseRepository(), new EditLockGuard(locks), clock),
        approvals)
        .registerOn(router);
```

Three things in it are not obvious:

- **`ExamService` takes two repositories.** The second serves `EXAM_LIST`'s question count.
- **`registerApprovalFeature` has to return the `ApprovalService`.** It currently builds one inline
  and returns `void`; `EXAM_SUBMIT`'s hook needs the instance. `registerGradingFeature` already has
  the shape, returning its listener.
- **The `EditLockGuard` must wrap the same `EditLockService` already registered**, not a second
  one. Locks live in that object's map, so a copy consults an empty world, refuses nothing, and
  looks exactly like the correct line.

If you would rather it live in a `registerExamBuildFeature` helper, the guard will fail and the fix
is to point it at the helper. That direction is deliberate: an extracted helper and an
extracted-but-never-called helper look identical from where the guard stands.

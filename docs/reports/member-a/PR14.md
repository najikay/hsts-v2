## 1. What it does

`BANK_LIST` with all four filters travelling to the server, paged; `QUESTION_GET` into a detail
pane; `QUESTION_IMAGE_GET` fetched lazily and only for a question that has one;
`QUESTION_VERSIONS` behind a panel that is not opened by default; `QUESTION_DELETE` with both of
its outcomes, including T-2.7's refusal naming the exams.

Three files, on the `DataView` shape: `BankCopy` (every sentence, FX-free), `BankSession` (every
decision, FX-free, tested against `FakeClientConnection`), `BankView` (nodes and nothing else).

**No Edit button.** The editor is E6.10 and lands with the lock integration it needs. A button
wired to nothing teaches a teacher that the screen is broken, which is slower to unlearn than a
control that has not appeared yet.

**No topic picker.** Ruling 7.6 made the topic filter an exact-equality lookup fed by
`BANK_TOPICS`, and neither the verb nor `findDistinctTopics` exists. The filter itself has been on
the wire since #30, so the lookup landing changes exactly one method,
`BankSession.availableTopics()`, and the picker appears. Until then the screen shows no picker
rather than an empty one.

## 2. The design worth reviewing: late answers cannot land

A teacher typing in the search box, or clicking down the list, has several requests in flight
whose answers can arrive in any order. Applying the last one to arrive puts rows on screen that do
not match the filters above them, or a question in the pane that is not the one highlighted.

Every request carries the generation it was issued under, and an answer from an older generation
is discarded. The counter is bumped by anything that changes what an answer would *mean*.

I planted this three ways rather than once, because picking the mutation while holding the check
in your head is how a single plant proves nothing:

| Mutation | Caught by |
|---|---|
| list generation check removed | `staleListIsDropped`, `staleFailureIsDropped` |
| detail generation check removed | `staleDetailIsDropped` |
| image generation check removed | `staleImageIsDropped` |

The delete path is deliberately **not** subject to this rule, and section 3's finding 2 is why.

## 3. The cold audit, which is the substance of this PR

Run after the code was written, against the code. It returned six confirmed findings and one
suspected. **I reproduced two of its claims before acting on them** (the server does not clamp an
out-of-range page; `WarnConfirm.show` delegates to `showAndWait` and therefore runs a nested event
loop). All seven are fixed. Every fix has a test, and every test was planted.

**1. A failed delete toasted forever.** `renderDialogs` cleared the other two notices and not this
one, and `render` is the `onChange` callback, so one timed-out delete produced a red toast on
every settle, filter and selection for the rest of the session. Added `dismissDeleteError()`
beside the two dismissers that already existed.

**2. The delete outcome could act on the wrong question.** `settleDelete` was the one settle with
no generation check, and the list is not disabled while a delete is in flight. Deleting #11005 and
then clicking #11001 closed the pane she had just opened, with no indication why; and a refusal
for #11005 was read against #11001, because the dialog named the exams and never the question.

The fix is *not* to drop the late answer the way a late read is dropped: the row really was
deleted, and a list still showing it would be a lie. So the id travels with the outcome, the
selection is cleared only when the question deleted is the one open, and the refusal names its
question.

**3. Deleting the last row of the last page said the bank was empty.** ⚑ The reload asked for the
page she was on, `BankBrowseService` clamps only a negative page, so the answer was an empty page
2. `NO_QUESTIONS` — "There are no questions yet" — then rendered under a count line reading
"Showing 0 of 40 questions". That panel exists precisely so a teacher is never falsely told her
bank is empty, and this was the one path that told her exactly that. The session now takes the
page from the answer and steps back to the last real page.

**4. The version diff could not see a replaced illustration.** The wire has three image actions
and `QuestionVersionDetail` carries only `hasImage`, so a teacher who swapped a wrong diagram for
a right one got "Nothing on the question itself changed" — a false sentence about the only reason
the version exists. **See section 4: this one is half a contract defect and it is cheap today.**
Meanwhile the fallback says what is true instead, and `authorName`, which *is* on the DTO and was
simply not compared, now is. The history line names the author too: on a co-taught course that is
the first question a teacher asks of a history.

**5. "Choose it again to retry" was an instruction the screen could not honour.** After a failure
the row stays selected, so clicking it fires no selection change. In the same state the pane read
"No question selected" beside a highlighted row. Now it has its own heading and an explicit Try
again.

**6. The course picker was empty for two of the three roles licensed to browse.** ⚑ It was built
from `LoginResult.courses()`, which is `CourseRepository.findForUser`, which is taught union
enrolled and touches neither `coordinators` nor `subjects`. The bank's read scope is wider on
purpose. So `rina.barak` — who holds a `coordinators` row and zero `course_teachers` rows *by
design*, and who is the approver in acceptance scenario 4 — would have opened the bank at the
defense, seen every question in her subject, and found a course dropdown with one entry in it.

The picker is now the union of her own courses and every course the bank has actually shown her.
**That is a repair, not the answer** — see section 4.

**7. Four assertions that could not fail.** All four were mine. `carriesTheBaseVersion` used a
fixture where `versionNo == latestVersionNo`, so swapping which token travels left it green;
`studentsAreNotOfferedTheBank` asserted false-is-false; the paging test had the fake echo the
asked page back; `namesEachField` varied exactly the fields the implementation compared. Fixed,
and the guard now has a guard against vacuity.

**8 (suspected, and it is real).** The confirmation dialog blocks on `showAndWait`, so a list
answer can land while she reads it and drop the row. `deleteSelected()` would then return
silently: she pressed Delete and nothing happened. There is now an explicit
`delete(displayId5, baseVersionNo)` and the view passes what the dialog described, so the delete
acts on the question she was actually shown.

**One mutation I could not catch, reported rather than papered over.** I wrote a test that
`hasNextPage` is taken from the payload rather than recomputed. `BankPage.hasNextPage()` is
literally `page + 1 < totalPages`, so recomputing it is an *equivalent* mutation and no test can
distinguish the two. The test was decoration, so I deleted it and left the delegation with a
comment saying it is not a guard. One rule with one home is still worth doing where it is not
worth checking.

## 4. Two things for you, both cheap now and not later

**4.1 `QuestionVersionDetail` cannot express a replaced illustration.** The contract is still
DRAFT, so one additive field — a length, a hash, anything that differs when the blob differs —
closes finding 4 properly. After the freeze it is an amendment plus a mapper plus two engine
tests. If you would rather not carry it, say so and the sentence stays as it is; it is honest
either way, just less useful.

**4.2 The course picker wants the same lookup the topic picker wants.** Finding 6's union is
complete only while a teacher's bank fits on one page. Both pickers are the same question — "what
may I filter by" — and both are answered by the reachable set the service already computes once
per request. Ruling 7.6 already schedules `BANK_TOPICS`; a `BANK_FILTERS` answering topics **and**
courses together would close both, and it is one verb rather than two.

I did not build either, because `common/protocol` and `common/dto/bank` are yours and ruling 7.6's
opening was for the topic lookup specifically. Say the word and I will draft the addition into the
contract for you to land.

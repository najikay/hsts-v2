# E6: the bank's three write verbs, and one line I could not write

**Create, edit and delete, over a service, against §3's guard column.** The read verbs are the next
PR. Read §1 first: this PR ships a feature that no running server can reach yet, and the reason is
a path permission rather than a design decision.

## 1. The gap, stated before anything else

`BankHandlers.registerOn(router)` is never called. The assembly line belongs in `HSTSServer.java`,
which is outside the paths E6 opened to me, and `Authorization.java` is the only file in
`server/core/**` I may touch. So the three verbs exist, are tested, and are unreachable from a
running server until one line lands beside the `LegacyQuestionHandlers` registration:

```java
new BankHandlers(sessionFactory,
        new QuestionService(new QuestionRepository(), new CourseRepository(),
                new UserRepository(), new QuestionIdAllocator(), Clock.systemUTC()))
        .registerOn(router);
```

What is already proven: `registersTheThreeWriteVerbs` runs `registerOn` against a real
`MessageRouter` and asserts all three land as authenticated handlers, that none is open, and that
`BANK_LIST` and `QUESTION_GET` are **not** registered here. The wiring is tested; only the caller is
absent.

Either add the line yourself, or open the file for the E6 registration the way you opened
`Authorization.java`. The read PR needs the same line, so one opening covers both. **No TODO boxes
are ticked in this PR** (E6.1, E6.3, E6.4 all stay open) because a reviewer could disprove them by
trying to add a question.

## 2. §3's table, as code

| Verb | Guard | On failure |
|---|---|---|
| `QUESTION_CREATE` | `requireTeachesCourse`, throwing | `FORBIDDEN` |
| `QUESTION_UPDATE` | `teachesCourse`, boolean | `NOT_FOUND` |
| `QUESTION_DELETE` | `teachesCourse`, boolean | `NOT_FOUND` |

Nothing composes the two and nothing chooses between them at runtime. Both are called against the
open transaction's data through a lambda over `CourseRepository.teaches`, never through the
process-wide directory, which is `ApprovalService`'s pattern.

`create` throws because the caller supplied the course. `update` and `delete` resolve the course
from a stored question, so unknown, soft-deleted and out-of-scope collapse into one `NOT_FOUND`
with one sentence, per §6.

Editing inserts version n+1 and leaves n untouched; `editWritesANewVersionAndLeavesTheOldOneAlone`
asserts the previous row's fields are unchanged, which is invisible from the new row. Deleting is
blocked or soft, never hard, and the blocked branch returns before the stamp: that rule has no
database backstop, because no foreign key fires on an `UPDATE`.

## 3. The cold audit, run after the code was written

Five defects and two weak tests. Three of the five were mine to fix and are fixed; two go to you.

**REPLACE carrying no file silently deleted the illustration.** A teacher opens an illustrated
question, presses Replace, her file picker returns nothing, and the server answered `OK` and wrote
version n+1 with no image. Gone from the bank and from every exam built on the new version. §4
gives `ImageAction` three states so that clearing is never implicit; `REPLACE`-with-nothing put the
ambiguity back. Now `VALIDATION`, naming both ways forward.

**The principal was one role-list entry from writing to every bank in the school.** §2's strongest
claim is zero mutating verbs, ever. On `QUESTION_CREATE` it is double-gated, since
`requireTeachesCourse` runs `requireRole` itself. On `QUESTION_UPDATE` and `QUESTION_DELETE` the
boolean `teachesCourse` performs no role check by design, so the only gate is one line in the
shared handler, and nothing tested it. `refusesThePrincipal` now covers all three.

**A draft with no course answered `FORBIDDEN` with a sentence written for the edit screen** ("that
question is not linked to a course, so it cannot be changed", on a create, naming no field). §6
gives malformed payloads `VALIDATION` with the field named, and `BAD_REQUEST` is deliberately
unused. Now `BankMessages.COURSE_REQUIRED`.

**My own comment named the wrong mechanism, which is the P-6 defect exactly.** I added a test
asserting that exotic Unicode spaces fold like ordinary ones and wrote that NFKD was responsible.
It is not. `Collator` at PRIMARY strength treats a space as completely ignorable:
`compare("ab", "a b")` is `0` before any exotic character is involved. Reproduced on JDK 21 under
three variants: with the NFKD pass deleted, five of my six assertions still pass; with `trim` moved
ahead of normalisation, all six do. So five were decoration and the comment was the thing that
would have stopped the next reader looking. Corrected, U+202F split out as the one case NFKD
genuinely earns, and `spaceIsIgnorableToTheCollator` added to pin what the rest actually rests on.

**Two of my tests named properties their assertions could not see.**
`stripsTheCourseCodeBeforeTheGuard` claimed its `teaches` assertion catches `strip`→`trim`; it
cannot, because `Authorization.teachesCourse` strips again on its own way through, so only the
allocator assertion carries that weight. Comment corrected, and worth knowing on its own: **the
strip is implemented twice, in the service and in the guard, and nothing checks the two agree.**

`keepCopiesTheImage` could not see aliasing, and my first fix for it was also decoration. I added
`isNotSameAs`, planted the defect by removing `QuestionVersion.getImage()`'s clone, and **it did not
fire** — the constructor's own clone means the new row never holds the test's array whatever the
getter does. The property is real, lives on the entity, and is already guarded correctly by
`EntityRoundTripTest.imageIsDefensivelyCopied`, which did fail under that plant. My assertion was
removed and the comment now points at the test that holds the property.

Four defects planted in total this round, four caught by their own tests.

## 4. Two things for you

**`QuestionEdit.changesImage()` is unreachable and its javadoc is wrong.** Zero callers in
`src/main`; the only references are three assertions in `BankDtoTest`. Its javadoc says the method
tells the handler "to look at `image()` rather than copy the previous version's blob forward", but
it returns `true` for `REMOVE`, where reading `image()` is precisely what the handler must not do.
The handler it names branches on `imageAction() == REPLACE` instead. `common/dto/bank` is yours, so
this is a report rather than a diff. Deleting the method or rewriting the sentence both work; the
risk of leaving it is that the next person to touch image handling calls it, because the javadoc
says that is what it is for.

**A product question, not a defect: spacing alone never separates two answers.**
`sameAnswer("1 2 3", "123")` is `true`, and so is `sameAnswer("red car", "redcar")`, because the
collator ignores spaces outright. This is the **safe** direction under §5's one-directional rule:
`utf8mb4_unicode_ci` gives a space a primary weight and would accept both pairs, so we refuse
things the database would allow, never the reverse. But §5's stated worst case is "a teacher told
two confusingly similar answers are too similar", and `1 2 3` against `123` in a sequence question
is not obviously that. Pinned as documented behaviour in
`spacingAloneNeverSeparatesTwoAnswers` rather than changed, because loosening it is a change to the
one-directional rule and that is yours to make. E6.11's live client check shares `sameAnswer`, so
whatever you decide applies to both ends at once.

## 5. Contract changes (still DRAFT)

`requireBankRead` was named in six places as a guard that would land with the handlers. It exists in
no code, and §3's table gives it no verb: all three scoped reads use the boolean `reachesCourse`,
and `BANK_LIST` was corrected from a guard to a filter because naming a guard there was a rule no
handler could implement. A throwing guard with no caller is a licence for a future handler to use
the wrong one, so it was not written.

§2, §3's prose, §5 and the header now name `reachesCourse`. Three mentions are deliberately kept as
history, each followed by its correction. **§7.7's ruling text is untouched** and annotated
beneath, not rewritten: the substance, two scopes composed nowhere, is what shipped. The header's
`Handlers:` line said `QuestionService`, which is the service; it now names `BankHandlers` and says
why the read verbs get their own class.

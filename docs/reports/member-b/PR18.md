## Scenario 9 — S-24 demonstrated on a running server

**9.1 is the most valuable result of the run.** Maya sat **two** seeded exams: Algebra (execution
1, 71, approved) and Java (execution 2, 100, `AUTO`, unapproved). Exactly **one** row appeared.

The unapproved 100 is absent. That is C-3 / S-24 holding on a live server rather than in a unit
test — auto-grading publishes nothing until a teacher approves — and it is the kind of rule that
is easy to assert in a test and easy to lose in a screen. The row also carried its own exam name
and course code: contract amendment v1.1 earning its place, since without it the row would have
read "71 / 100" with no way to tell which exam.

**9.2 passed.** The checked form opened from the row, with header, attempt line, seven questions,
per-question points, and "Your answer" / "Correct answer" tags. **The "Reviewed by your teacher"
marker was correctly absent** — Maya's 71 was never overridden, and the marker keys on the two
scores *differing* rather than on a final score being present, which every approved row has.

Styling is deliberately plain: the marking colours are for the lead's screen review, and every
outcome carries a **word** as well as a class, so the form never depends on colour alone.

## Bugs

**B-1 → Fixed.** `docs/DEMO_ACCOUNTS.md` now carries "⚠ These accounts do not exist until the seed
has been loaded", names `RepositoryUserDirectory` as the authority, and adds the diagnostic — load
the seed before suspecting the credentials. Verified by reading the file; 1.1 then passed against
a reseeded database. Never a code defect.

**B-2 → Open (low, cosmetic).** The server prints a red `ERROR` about thirty seconds into
start-up: `Log4j2 could not find a logging implementation`. Something on the classpath uses the
log4j2 API with no binding, and it falls back to SimpleLogger. Nothing is broken — the server's
own logging is logback and every later line appears normally. It matters because **this is the
terminal visible during the defence**, and a red ERROR line invites a question that costs more to
answer than to prevent. Appears on the `SeedMain` path too. Fix: add `log4j-to-slf4j`, or exclude
the log4j2 API from whatever drags it in. Small either way.

## ⚑ Still open — case 9.5

`omer.katz`'s paper showed **no "Not answered" questions**.

Everything I can check statically says it should work. The seed is right: four dashes in §9.1.1,
and 52 answer rows loaded rather than 56. The grading path is right: a question with no answer row
produces a null selection (`AutoGrader` line 150), which reaches the wire as a null `chosen` and
renders as "Not answered".

**What I do not know is whether his checked form opened at all**, and the two possibilities need
opposite fixes:

| If | Then |
|---|---|
| A score header appeared, four questions labelled **Wrong** | Rendering defect on a path whose unit tests pass — the more serious finding |
| A "not available" sentence appeared | A gate refused. The interesting candidate is gate 2, which would mean his grade is not `APPROVED` in the reseeded data, contradicting §9.1 |

The case stays unrecorded until that is answered. Recording it either way now would put a
guess into a document we defend.

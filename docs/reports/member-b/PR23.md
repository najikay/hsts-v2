## B-4 — Select-all selected nothing visible *(fixed here)*

Select-all updated the **session's** selection and not the **table's**. The button enabled and
the confirmation counted correctly, so the right rows were approved — but a teacher could not
*see* what she was about to approve, on the one action that cannot be undone.

The screen wired selection **table → session** and never **session → table**.

`render()` now drives the table's selection from the session, inside the same re-entrancy guard
the queue rail already uses, and **returns early when the two agree**. That early return is not
an optimisation: a render happens on every session change *including the one a teacher's click
caused*, so reselecting unconditionally would fight her mid-click.

**Why no test caught it.** The session tests pass because the session is genuinely correct —
`selectAllApprovable()` ticks exactly the right rows. The defect is in the view, which is
coverage-excluded by design. This is the class of defect a manual pass exists to catch, and it
is the argument for tomorrow's pass in one example.

## B-5 — My Grades truncated the date *(fixed here)*

The Approved column read **"23 Au…"**. The table divided its width evenly, so a date got the same
room as a two-character course code — and the column a student reads to know when her grade
arrived could not show a date. The "Teacher's note" header was clipped for the same reason.

Preferred widths per column, sized to content, still adaptive to the window.

Found by **looking at the rendered screen**. `MyGradesCopyTest` asserts the date formats to
"20 Aug 2026" and passes — it never sees a column. That is the honest limit of testing copy in
isolation, and worth saying out loud rather than treating the green tests as coverage of the
screen.

## B-3 — `teacherComment` had no wire *(reported here, already fixed by the lead)*

**Read everywhere, written nowhere.** It was on the student wire, the teacher wire, both copy
classes and both screens. The only thing that ever set it was the seed loader: no request DTO
carried a comment field, and no service called `Grade.setTeacherComment`.

So **S-22 had no path through the application** — a teacher could not leave a student the one
piece of free text the student is allowed to read, and acceptance case 8.4 could not pass.

**The seed masked it.** `yael.azulay` has a seeded comment, so every screen rendered one and
looked finished. It was visible only on trying to *write* one.

**Already fixed while this branch sat uncommitted.** The lead landed GRADING amendment A3 —
option A of the two put forward, the comment riding `GradeOverrideRequest`. `main` is merged into
this branch, so his comment box and my selection fix now sit in the same dialog. The register
records B-3 as Fixed and credits A3.

**Case 8.4 is left ⚠, not ticked.** The wire exists, but nobody has watched a comment travel to a
student. Marking it passed on the strength of the code existing would defeat the point of a table
whose whole claim is that somebody saw it work. It wants a re-walk, which is minutes.

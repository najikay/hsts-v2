## 1 · §11 `seed_id` — describing the key that exists

Reworded. `notifications` has **no `seed_id` column**; the loader keys idempotency on
**recipient + type + title**, which is unique across the eight rows.

The naming column stays, and the section now says why: the composite key is unusable in a
sentence. An acceptance case or a failing assertion needs to name *which* notification, and
`N-EXEC-CLOSED-ALG` does that where "the row for user 1 with type EXECUTION_CLOSED and title
'בחינה הסתיימה…'" does not. It is documentation vocabulary.

And the trigger is recorded: the composite holds only while no recipient gets two notifications
of the same type and title. Seed a repeating one — two grade publications to the same student —
and it collapses. **That** is when the column becomes real, rather than when someone finds it
tidier.

## 2 · D9 — authorship as a rule

`question_versions.created_by` had no stated source, so the rule lived only in chat. Now in §7:

- **v1 of every question** → the course's **first-listed teacher in §4**: Algebra and Calculus
  `2 dana.cohen`, Java `4 avi.mizrahi`, Databases `6 michal.sharon`.
- **A second version in a co-taught course** → the **co-teacher**. Java (21) is the only co-taught
  course, so this resolves to exactly one row today: **`21003` v2 = `5 tamar.shani`**. The other
  two second versions sit in singly-taught courses and stay with the first-listed teacher —
  `11005` v2 is `dana.cohen`, `22004` v2 is `michal.sharon`.

I recorded *why* the second clause exists: T-2.2's "the previous version remains in the bank" is
more convincing when a version history shows two names, and `21003` is the row that demonstrates
it. The rule also re-resolves itself if Java stops being co-taught or another course gains a
co-teacher — which is the argument for a rule over 43 hand-written values, and the question a
reader would otherwise ask.

**No table shape changed**, so `SeedDocument` is unaffected whichever order this and Omar's parser
land in.

## The four rules, and why each has a test

**Idempotent — and it does not re-stamp.** Re-approving counts in `alreadyApproved` and is not an
error (§6, H12.2). The test that matters is the second one: approving an already-approved grade
*as a different teacher* leaves `approved_by` and `approved_at` as they were. An implementation
that simply called `approve()` again would pass a naive idempotence test while quietly rewriting
who signed the grade off — losing the audit trail F8.3 exists for.

**Partial success is a normal outcome.** Ids the caller may not approve and ids that do not exist
both land in `refused`, and the rest of the batch still lands. Approving eight of ten is a result,
not a failed transaction.

**"Not yours" and "does not exist" are the same answer.** Same no-oracle rule as E13.1: the
response cannot be used to discover which grades exist. Tested by asserting the two results are
equivalent rather than merely that both refuse.

**Ownership is resolved per grade.** A bulk request can span executions, so the executing-teacher/
author check runs for each id rather than once. `ExecutionContext` already carried
`executingTeacherId` and `authorId`, so this needed no new read.

## E12.4's `→ stored`

When the last `AUTO` grade of an execution becomes `APPROVED`, `ScoreStatistics` is computed from
the final scores and written to `exam_executions.stats` **in the same transaction**. Three
decisions worth review:

| # | Decision | Why |
|---|---|---|
| a | Completion is detected by reading **all** grades of the execution, not by a count | A count and a projection would read the same rows twice in one transaction and could disagree. One read answers both "is anything left?" and "what are the scores?". |
| b | Freezing is silent when grading is incomplete | A bulk approve covering half a class is a normal step. Tested: seven rows still `AUTO` → nothing written. |
| c | Notifications are sent **after** all approvals and freezing | A student must never be told a grade is ready by a transaction that then rolls back. Nothing after that point can fail the approval. |

`ScoreStatistics` → `ExecutionStats` is bridged in exactly one private method. They are
deliberately different types — the stored one drops `count` and `passCount`, both derivable — and
one bridge means one place for that mapping to be wrong.

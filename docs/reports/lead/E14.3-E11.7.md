### 2.2 Decisions

**The axis rules are the requirement.** v1's statistics view failed its review on a chart whose
bars were relative to each other on an axis that started wherever it liked. Three rules are
encoded in `StatChartLogic` and asserted in a nested `Honesty` test class:

1. **Zero-based.** `yTicks` always starts at 0 and there is no method that could move it.
2. **Headroom.** The top is 15% above the tallest bar, rounded up to a whole tick, so the
   tallest bar never touches the frame. Asserted for ten class sizes from 1 to 99. The one
   deliberate exception is a percent axis at 100%: a class entirely inside one bucket really is
   100%, and running the axis to 150% to preserve headroom would invent room that does not
   exist.
3. **One ruler.** Bars and overlay markers use the same mapping from score to x, so a mean of
   72.5 is drawn against the bars rather than merely near them. `xForScore(60, 500)` and
   `slotWidth(500) * 6` are asserted equal, which is the property that would break first if
   somebody re-derived either side.

**Nothing is recomputed.** Mean, median and σ are read from the execution's frozen statistics.
σ is the **population** form (divisor `n`) because that is what `ScoreStatistics` stored;
recomputing with the sample divisor would shift the ±1σ band about a point and look like a
rendering bug. Percentages divide by the stored participant count, so the chart and the stat
cards above it cannot disagree.

**Empty is not insufficient.** Nobody graded (`EMPTY`, "No results yet") and one result
(`INSUFFICIENT`, "Not enough results to chart") are different sentences to a teacher, and
neither of them is a chart. The threshold is 2: two scores have a spread, a mean between them
and a meaningful σ; one has none of those. Both states render through `EmptyState` inside the
same box as the plot, so the card does not change height when results arrive.

**Rose-palette caution, honoured.** Bars are `-hsts-accent`; **markers and the σ band are
neutral ink** (`-hsts-muted`, `-hsts-text`, `-hsts-border`) in every palette. On Rose the accent
sits close to `-hsts-danger`, and a mean marker in a red-adjacent colour reads as an alarm about
the class rather than as a statistic. Mean and median are additionally told apart by **shape**
(dashed vs solid), not only by colour — a colour-blind teacher and the F9.4 printed report both
need that.

**Looked-up values are colours only.** Every radius, width and dash array in the new CSS section
is a literal, per the rule the token layer is built around and the E4.24 smoke test enforces.

**Animation budget.** Staggered grow-up, step 14 ms capped at 126 ms, each bar 120 ms → 246 ms
total, inside PRD §4.1's 250 ms. Interruptible: a data change stops the running timeline instead
of layering a second one over it. The scale toggle deliberately does **not** replay the
entrance — it is a change of unit on a chart already on screen, and re-animating would read as
new data arriving.

### 2.3 How Member B consumes `StatChartData` (E14.3b)

The teacher's results screen has the execution's stored statistics on the grading wire. Map them
straight across, and do not derive anything:

```java
StatChartData data = StatChartData.of(
        stats.deciles(),            // List<Integer>, exactly ten counts, ascending
        stats.mean(),
        stats.median(),
        stats.standardDeviation(),  // population form, divisor n — do NOT recompute
        stats.count());             // attempts carrying a final score

StatChart chart = new StatChart();
chart.setHeading(examName + " · execution " + code);
chart.setData(data);
chart.bindTheme(themeState);        // optional; CSS already handles colour
```

Four things to know:

1. **`deciles` must be exactly ten entries**, index `i` = `[i*10, i*10+9]` and index 9 =
   `[90, 100]`. That is what `ScoreStatistics` produces; anything else throws at construction
   rather than drawing a wrong chart.
2. **An execution with no statistics is `StatChartData.empty()`.** The server answers an empty
   `Optional` rather than a record of zeros, so `Optional.map(...).orElseGet(StatChartData::empty)`
   is the whole mapping. Do not synthesise a zero-filled record: the chart would then show
   `INSUFFICIENT` copy for something that is genuinely `EMPTY`.
3. **Do not recompute σ or the pass mark.** Both are frozen on the execution (F8.5), and a
   second computation with a different divisor or threshold is the exact bug class the seed
   document warns about.
4. **Calling `setData` again replays the entrance**, which is what you want when the execution
   picker changes. `setScale` does not.

The component is size-agnostic: give it a `prefHeight` (280–320 works well) and let the parent
drive the width. Below roughly 420 px the bucket labels will start to crowd; the results screen
should keep the chart in the main column rather than a side panel.

### 3.2 Decisions

**Debounce at 500 ms, report on refocus.** Window managers hand focus around for fractions of a
second when a notification appears or a tooltip opens; reporting those would bury one real
thirty-second absence under forty meaningless ones. And nothing is sent on blur, because the
duration is the fact the teacher weighs and a duration does not exist until the absence has
ended. A consequence worth stating at the defence: a student who never comes back produces no
report at all, which is correct — her attempt ends by expiry and the monitor already says so.

**No live attempt is an `OK`, not an error.** She can be away when her time runs out, so the
refocus arrives after the server has force-submitted her. A `CONFLICT` there would make a
correct client log failures during every exam.

**Accumulating, not first-wins.** This is the deliberate difference from `IntegrityFlag`, which
keeps the first report because "when did this begin" is what a teacher acts on. Here the useful
facts are "how often" and "how long in total": one 40-second absence and eight five-second ones
are different situations that a first-wins record would render identically.

**No student id, no attempt id on the wire.** The server resolves the caller's own live attempt
through `AttemptRegistry`, on the same P-5 rule as every other student verb, so no client can
report an absence for anybody else or inflate somebody else's count.

**Signal, not verdict — enforced, not just documented.** Two tests assert the negatives: nothing
is pushed to the student, and no notification is raised. The monitor chip is `hsts-chip neutral`
and the test asserts it carries neither `danger` nor `warn`. There is no student-facing UI
anywhere and no auto-penalty of any kind.

**The honest limit is on screen.** The chip's tooltip says it: detection runs on her own
machine, benign reasons are common, this is something to weigh rather than a finding. Same
framing as the discovery fingerprints. Better on the screen the teacher acts from than in a
document she will not open.

**Lifecycle.** The tracker starts with a live paper and never with a finished one; it stops on
submit, on force-submit, on a resume that finds the attempt over, and on leaving the screen. The
window listener is attached only when the paper takes over (the code and identity screens are
not the exam) and detached on every exit, so nothing outlives the attempt on the long-lived
`Stage` the whole app shares. An absence in progress when the attempt ends is discarded rather
than reported. `start()` resets the client's counters because the **server** holds the running
total — a client replaying its own history across a reconnect would double every absence.

## 4. What the lead double-checks

Things a reviewer should look at first, in order of how expensive they would be to get wrong:

1. **The percent axis cap.** `axisMax(PERCENT)` clamps at 100, which is the only place the
   headroom rule is deliberately suspended. Confirm the top gridline still equals the axis
   maximum in that case (asserted in `percentAxisNeverExceedsOneHundred`), because a top tick
   that no longer sits on the frame is a chart that looks broken rather than one that lies.
2. **The tick step is computed once.** `axisMax` and `yTicks` share `tickStep(Scale)`. An
   earlier draft derived the step a second time from the rounded maximum, which for eight
   students produced an axis running to 12 labelled only up to 10. If either method is edited,
   they must keep using the same step.
3. **`MonitorRow`'s new component is appended last and nullable**, and the ten-argument
   constructor is kept. That is what makes A2 additive rather than breaking; a reviewer should
   check no existing call site was rewritten to pass an explicit `null`, because that would turn
   a compatible amendment into a diff that looks like a break.
4. **`clearFlags()` now clears two maps.** The name did not change (an existing test names it),
   but the behaviour did. Anyone adding a third piece of monitor state should add it there too.
5. **The gallery numbers are hard-coded from the seed document**, not derived. That is
   deliberate: the gallery is where a reviewer checks the chart against §9.1 by eye, and a chart
   that computed its own fixture could only ever agree with itself. If the seed changes, this
   section must be updated by hand.
6. **`AttemptTracker.attentionOf` is a `default`.** It exists so the study bot's
   `FakeAttemptTracker` stays untouched. If a second real implementation ever appears, it should
   override rather than inherit the empty answer.
7. **E14.3b is Member B's.** The component is done and gallery-verified; the results-screen
   wiring is not in this pass and the TODO entry now carries the mapping recipe. Nothing in E14
   should recompute σ or the pass mark.
